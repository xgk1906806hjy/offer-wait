# offer 请等等 · 产品方案（PRD v0.1）

> **一句话**：把 offer 签字前的纠结，交给一群利益无关的过来人，换回一张「签字前必须问清楚的清单」。
>
> **定位差异**：不是"投票决定接不接"，而是**限时的、带判决的尽调**。

---

## 1. 为什么是 offer：五条硬条件，五条全中

沿用的判据（不可逆 / 熟人不可用 / 有更轻的替代方案 / 一次性决策 / 可拦截）：

| 条件 | offer 场景的对应事实 |
|---|---|
| 动作不可逆 | 点了接受就拒掉其他、放弃应届生身份窗口、可能要搬家、签了三方还有违约金 |
| 熟人不可用 | 朋友替你高兴，不替你判断；父母只看稳定；**同学可能是同岗位竞争者**，根本不能问 |
| 有更轻的替代 | 延后答复 3 天、要书面细节、谈一次薪、要一份排班记录、去问两个在职的人 |
| 一次性 | 签完即结束，不需要判决者长期陪伴 |
| 可拦截 | 存在明确的"点接受之前"的那 24–72 小时 |

**关键判断：这里缺的不是意志力，是信息。** 消费冲动是"想要"，offer 焦虑是"不知道"。
所以产品重心必须从"投票"移到"提问"——**投票只是手段，问题清单才是交付物**。这一条决定了后面所有设计。

---

## 2. 和《钱包请等等》的三处不同（照抄会死的地方）

| # | 钱包请等等 | offer 请等等 | 为什么必须改 |
|---|---|---|---|
| 1 | 二元判决：通过 / 驳回 | **三态：接 / 再等等 / 别接** | offer 的正确动作大概率是"先去补信息"。二元会逼着用户在没有信息时做决定，也逼着审批人瞎判 |
| 2 | 审批人只需表态 + 写理由 | **必须回答至少一个"签字前该问的事"** | 只表态的审批没有信息增量。强制回答，把"围观"变成"尽调" |
| 3 | 结果是"省了多少钱" | **结果是可执行清单**（未答问题 + 三条固定动作），可导出、可发邮件给 HR | 钱是即时的，offer 是延迟验收的。用户离开产品后还需要这份清单 |

另外两处小改，但很关键：

- **倒计时是一等公民**。offer 有 deadline，天然稀缺。按截止时间排序，越急越靠前。
- **复盘挂在决定之后**。三个月后回访"哪句话真的帮到你了"，这是唯一能证明产品有用的证据（也是钱包请等等目前缺的那一环）。

## 3. 用户与场景

**C1 校招应届生（旺季：9–11 月、3–4 月）**
纠结：接不接唯一 offer / 等等看补录 / 城市与户口 / 三方违约金。
人群特征：信息最不对称、最容易问同学（而同学是竞争者）、最容易被"先签了再说"骗。

**C2 社招 1–5 年（全年，集中在金三银四）**
纠结：涨薪 vs 加班、期权占比、团队刚裁过员、汇报线、base 地选择。
人群特征：有判断力但缺外部视角，且**不能在公司内打听**。

**C3 审批人：过来人**
动机三层：① 我踩过的坑不想别人再踩（利他）；② 判断力被认可（身份）；③ 反正是刷手机（低门槛）。
**这一侧才是冷启动的真正难点。**

---

## 4. 核心流程

```
① 脱敏提交（岗位/行业/城市/区间/截止/一句话纠结/有没有其他选择/已问过什么）
        ↓ 系统按岗位生成 3–4 个「签字前必须问清楚」的问题
② 广场（按 deadline 排序）
        ↓
③ 陌生审批人：选三态 → 写理由（≥10 字）→ 至少回答 1 个问题
        ↓ 先投后看：投完才看得到别人的判断与理由
④ 判决 + 行动清单（未答问题 + 三条固定动作）
        ↓
⑤ 自己做决定（接 / 拒 / 还在拖）
        ↓
⑥ 三个月后回访：哪句话真的帮到你了
```

---

## 5. 关键机制

**5.1 为什么要"先投后看"**
沿用原产品的防从众设计：未投票时**连票型分布都隐藏**，只显示"已有 N 位过来人审过"。
一旦先看到"7 个人都说别接"，后面的人只是在附和。这里要的是第一反应。

**5.2 问题从哪来**
三层，从便宜到贵：
1. 模板层：通用三问（汇报人 / 离职率 / 试用期考核）+ 岗位特化问（投行问项目储备，产品问期权条款，管培问是否真轮岗）；
2. 投票层：审批人自己写的问题与答案；
3. 沉淀层：把高频"被问倒"的问题回灌进模板（**这是唯一会随时间变厚的资产**）。

**5.3 判决的呈现**
三色票型条 + 印章（可接 / 再等等 / 别接）。印章是个小设计：它把"网友意见"变成了"公文"，用户更愿意截图分享——但分享的是**结论和清单**，不是总包。

**5.4 反炫耀（决定生死的一条）**
- 总包只填区间，不填精确数；
- 公司名默认脱敏（"某 + 行业"）；
- **不显示最高票、不做"offer 排行榜"、不做"薪资 PK"**；
- 一旦广场出现"35k×16 求比较"，真实求助者立刻消失，产品退化成牛客 offer 版。

**5.5 结果闭环**
"还有 N 个问题没人替你问"→ 直接给一份可复制的邮件正文。**用户拿着这张清单去找 HR，才算真的用上了这个产品。**

## 6. 供给侧冷启动（最难的部分）

需求侧不缺，缺的是"愿意认真审的人"。

1. **按行业开小广场**，不做大而全。前期只做 3 个：互联网研发、金融、快消/外企。
2. **过来人认证**：在职/曾任职打标（不公开公司，只标"我在同类公司待过 N 年"）。没有认证的人可以投票，但**答案不进清单**。
3. **审 3 份才能发 1 份**（贡献换提问权）。这条能同时解决供给和"白嫖"。
4. **冷启动兜底**：真人不足时，用模板问题 + AI 预答填充，但必须**显式标注"这是机器生成的，不是人"**。绝不能假装有人审。
5. **传播素材**：小红书发"我拒了一个 30w 的 offer，因为网友问了我三个问题"——内容是清单，不是薪资。

## 7. 指标

- **北极星：签字前被回答的问题数 / 周**（不是 DAU，也不是投票数——它衡量的是"信息真的补上了吗"）
- 核心漏斗：提交 → 24h 内被审 ≥3 次 → 拿到 ≥1 条有效回答 → 做出决定 → 90 天回访
- 质量指标：理由字数中位数、回答率（答题数/浏览数）、"送花"数（有用投票）
- **反指标**（一涨就要查）：炫耀帖占比、平均总包金额（涨了说明用户结构跑偏）、审批耗时（太快说明在玩梗）

---

## 8. 商业化与信任底线

**可以卖**：企业"经得起提问"认证（HR 主动提供团队信息）、薪资与流程数据服务（脱敏聚合）、谈薪与合同风险检查（C 端增值）。

**绝对不能卖**：判决结果、优先曝光、删差评、按公司定制的"好评"。

> 这个产品的全部价值，就是审批人敢说真话。卖一次判决，产品就死了。

---

## 9. 风险

| 风险 | 说明 | 应对 |
|---|---|---|
| 名誉权 | "某公司" + 负面评价，仍可能被识别 | 默认脱敏；只允许描述"团队/岗位"不评价"公司"；投诉即隐藏 |
| 法律意见 | 用户会问"三方违约金""竞业" | 只做经验分享，显式免责，涉法引导至律师 |
| 信息真伪 | 有人编 offer 骗建议，或凡尔赛 | 区间化 + 举报 + 不展示金额排名；异常账号降权 |
| 样本偏差 | 广场天然偏爱"劝退"，投票者可能是没工作过的学生 | 认证标注；展示"投票人背景分布"；不显示单一结论 |
| 供给不足 | 冷启动空转 | 见第 6 节；宁可显示"还没人审"，也不要用假回答 |

## 10. MVP 范围

本原型已实现（`index.html` + `app.js` + `styles.css`，纯前端、无依赖、数据存 localStorage）：

- 广场（按 deadline 排序、倒计时、脱敏展示）
- 提交（表单校验、按岗位生成 3–4 个必答问题）
- 审批（三态 + 必填理由 + 至少答 1 题 + 先投后看）
- 结果（票型条、印章、行动清单、全部理由）
- 我的（战绩、我提的 offer、做决定、复盘弹层）
- 5 条种子数据，覆盖校招/社招、有无其他 offer、期权、裁员等典型场景

**未做（下一步）**：真实后端与账号、过来人认证、行业小广场、理由"送花"、清单导出为邮件、90 天回访调度。

---

## 11. 明确不做

- 不做 offer 比较 / 薪资排行榜（会杀死真实求助）
- 不做"AI 帮你决定"（用户要的是**替罪羊**，不是答案；给答案的产品既无传播也不担责）
- 不做大额不可逆决策（买房、手术、离婚）——责任太重，没人敢背书
- 不做通用"人生审批"，先在一个垂直场景把供给侧跑通
